# Проверка соответствия User Stories

## User Story 1 - Рассчитать отбой

**Статус: полностью реализовано.**

История: студент с нерегулярным режимом сна хочет рассчитать долг сна, время отбоя и оптимальное время сна на сегодня.

Реализация:

- Кнопка в Telegram menu: `🛏 Рассчитать отбой`
- API endpoint: `POST /planning/bedtime`
- Настройка профиля: `PUT /users/{telegram_id}/profile`
- Локальное хранение результата: таблица `recommendations`
- История: `GET /users/{telegram_id}/history`
- Данные профиля: `wake_time`, `target_sleep_minutes`, `timezone`

Acceptance criteria:

1. После онбординга пользователь может открыть сценарий в один клик - реализовано через кнопку `🛏 Рассчитать отбой`.
2. Если есть время подъема и хотя бы одна запись сна, бот считает долг сна и рекомендует отбой - реализовано через `generate_bedtime_plan`.
3. Если данных мало, используется базовый ориентир и пользователь видит пояснение - `snapshot.baseline_used = true` и текст `Данных пока мало`.
4. После рекомендации предлагается напоминание - `snapshot.reminder_offer = true`.
5. Результат сохраняется в истории - рекомендация сохраняется в SQLite.
6. Текст понятен без пояснений - текст содержит отбой, подъем, долг сна, длительность и простые действия.

## User Story 2 - Power nap и медитация

**Статус: полностью реализовано.**

История: молодой специалист хочет быстро восстановить концентрацию через power nap или медитацию.

Реализация:

- Кнопки в Telegram menu: `⚡ Power nap`, `🧘 Медитация`
- API endpoint: `POST /recommendations/day-recovery`
- Поддерживаемые варианты: `power_nap`, `meditation`
- При наличии профиля и истории считается долг сна
- Если данных мало, бот спрашивает свободное окно
- Результат сохраняется в истории

Acceptance criteria:

1. После онбординга пользователь выбирает power nap или медитацию в один клик - реализовано.
2. Если есть время подъема и запись сна, показывается долг сна и рекомендуемая длительность - реализовано.
3. Если данных мало, бот спрашивает свободное время - реализовано в aiogram FSM и в `snapshot.needs_free_time_input`.
4. После рекомендации предлагается напоминание - `snapshot.reminder_offer = true`.
5. Результат сохраняется в истории - реализовано.
6. Текст понятен без пояснений - рекомендации короткие и пошаговые.

## User Story 3 - Быстро заснуть и хорошее пробуждение

**Статус: полностью реализовано.**

История: человек с проблемным сном хочет техники быстрого засыпания и методики хорошего пробуждения.

Реализация:

- Кнопки в Telegram menu: `💤 Быстро заснуть`, `🌅 Хорошее пробуждение`
- API endpoint: `POST /recommendations/sleep-technique`
- Поддерживаемые варианты: `quick_sleep`, `good_wake`
- Выбор техники зависит от качества сна, длительности сна и времени подъема
- Если данных мало, бот спрашивает качество сна или самочувствие после пробуждения
- Feedback endpoint: `POST /recommendations/feedback`
- История: `GET /users/{telegram_id}/history`

Acceptance criteria:

1. После онбординга пользователь выбирает технику засыпания или пробуждения в один клик - реализовано.
2. Если есть профиль и запись сна, техника подбирается по количеству сна, качеству и времени подъема - реализовано.
3. Если данных мало, бот спрашивает самооценку - реализовано в FSM.
4. После рекомендации бот просит оценить полезность - `snapshot.feedback_prompt` и endpoint обратной связи.
5. Результат сохраняется в истории - реализовано.
6. Текст понятен без пояснений - текст короткий, без медицинских обещаний и псевдонауки.
